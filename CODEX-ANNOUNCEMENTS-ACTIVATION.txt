WHAT IS BUILT

- Public announcements at /announcements/, styled to match the navy/cream site.
- A compact homepage link, shown after the service endpoint is connected.
- Post announcements in Admin opens /announcements/manage/.
- Separate server-checked owner/editor accounts. The existing admin PIN is not
  used to authorize live announcements.
- Owner creates one-use posting links, valid for seven days, and can revoke
  editor access. Removing access invalidates that person's sessions immediately.
- Use a test person fills Test poster and test-poster@example.test. This is a
  synthetic login identifier; no email is sent. The owner shares the posting
  link privately and the person chooses a password.
- Editors can preview, save drafts, publish, edit and remove announcements.
  They cannot add users or change the schedule settings through this account.
- Plain text, Hebrew, line breaks and optional removal after a New York date.
- First publication queues one encrypted Web Push alert. Drafts and subsequent
  edits do not send another alert. Concurrent edits reject stale revisions.
- Visitors explicitly enable notifications on their own device. No permission
  request happens until that button is pressed. They can turn them off there.
- iPhone installation help; actual phone delivery still needs verification.

The activation script deploys the new Worker, uses the actual returned service
URL, verifies server protection, and updates data/announcements.json. It creates
a bootstrap hash as a server secret if no owner exists. The private owner setup
link is saved in a new Lakewood-Announcements-Setup-*.txt file in the user's home
directory, outside Git. Its path is printed; the raw token is not printed.
If an owner already exists, the script preserves the owner and notification keys.

change, explain the actual response and get the user's decision. Do not change
