# Golden fixture

`golden.json` is the reference output of this app's calculation engine. It exists so that a
**port of this app to another language can prove it is correct**, rather than being eyeballed
against a printed chart.

Everything in it was produced by the code in `js/`, running in a browser against this
folder, with the shipped default settings (Lakewood, Hebrew, America/New\_York). It is
regenerated by `generate-golden.mjs` and cross-checked against the real rendered chart by
`verify-rendered.mjs`.

If you are porting this app: **get this file passing before you write a single line of user
interface.** Nothing downstream is worth building on an engine that is a minute out.

---

## The rule

Reproduce every string in `seasons[].rows[]` **exactly, character for character**, including
the underline sentinels and the line breaks. There is no acceptable tolerance on the strings.

For the raw numbers in `zmanim[]`, compare `day` (a fractional local day) to within 1e-9.
That is far tighter than a minute, and any port that is further out than that has a real
difference in the solar maths, not a rounding difference. The `time` string next to it is
what actually reaches the page, and that one must match exactly.

## Escapes

The strings carry characters that are invisible in an editor, so they are written out:

| In the file | Really |
|---|---|
| `{U}` | U+E000, the underline-start sentinel |
| `{/U}` | U+E001, the underline-end sentinel |
| `{NB}` | U+00A0, no-break space |
| `{LF}` | a newline |

The separator between two times is `{NB}/{NB}`, a slash with a no-break space on each side,
so a pair can never wrap onto two lines. That is a real no-break space, not a plain one, and
comparing against a plain space is the first mistake to make here.

## Raw engine output, not rendered output

These are the strings the engine produces, before anything renders them.

`underlineTime` writes a no-break space immediately after the underline sentinel, so every
underlined value reads `{U}{NB}7:30{/U}`. The renderer **strips whitespace straight after
the sentinel** (`nl2br` in `js/ui/sheet-view.js`, `weekNl2br` in `js/ui/week-view.js`),
because that space showed as an uneven gap in front of underlined times on the page.

So there are two comparisons and they are not the same one:

- Your engine's output, against this file as it stands.
- Your rendered output, against this file with that strip applied.

`verify-rendered.mjs` does the second, and its `plain()` is four lines long. Copy it.

## What is in the file

| Key | Contents |
|---|---|
| `meta` | The exact settings used, the escape legend, and the note above |
| `formatting` | `formatTime`, the minute rounding, `underlineTime`, `normalizeTimeList`, `splitLinesInHalf`, over the inputs that pin their edges |
| `years` | Hebrew years 5700 to 5900: Rosh Hashana serial and date, weekday, year length, year type, leap. 201 rows that pin the molad arithmetic and all four dechiyos across two centuries |
| `hebrewRoundTrip` | `dateFromHebrew` and back, every month of 5786 to 5790, leap months included |
| `calendar` | Every day from 2025-09-01 to 2029-09-01: Hebrew date in both spellings, day of year, year type, and any parsha, special Shabbos, Yom Tov, Rosh Chodesh, בה"ב, fast, or assur melacha on it |
| `zmanim` | All 21 named zmanim for every day of 2026, as both a fractional day and a formatted time. Covers both DST cutovers and both solstices |
| `seasons` | 26 season-years (קיץ and חורף, 5781 to 5793): the week list, the page split, the weekday chart's aligned page split, and every built cell of every row, plus the weekday chart's own rows |
| `seededFirings` | Every week where one of the three seeded rules fires, and the cell value it produces |
| `edgeCases` | The named traps, each as a labelled pointer: DST cutover days, the spring-window-only test, the plag window boundaries, ט' באב in both configurations, every parsha-less Shabbos and how it is labelled, and which year types the season range exercises |

### Two things in `seasons[]` that are easy to get wrong

**`builtAs`.** A row is built with its **page's** effective season, not the sheet's. A שבת
חורף page holding any week past the spring DST cutover prints as a full שבת קיץ chart, twelve
columns, for that whole page, including the earlier weeks on it. So a חורף season's later
rows carry `builtAs: "kayitz"` and have columns B through L rather than B through I. This is
`pageEffectiveSeason` in `js/ui/sheet-view.js`, and the generator got it wrong on the first
pass until `verify-rendered.mjs` caught it.

**The year range.** 5781 to 5793 is the shortest run that exercises all six year type and
leap combinations the parsha table is keyed on: 3P, 4M, 5P, 3M, 4P, 5M. `edgeCases.yearTypes`
lists which year covers which, so a shorter range shows up as a hole rather than passing
quietly.

## Regenerating

```bash
python3 -m http.server 9611
node fixtures/generate-golden.mjs > fixtures/golden.json
```

Then check it against the app itself, for a season on each side of the spring cutover:

```bash
PORT=9611 SEASON=choref YEAR=5787 node fixtures/verify-rendered.mjs
PORT=9611 SEASON=kayitz YEAR=5786 node fixtures/verify-rendered.mjs
```

Both need `playwright-core` and a Chromium binary; set `CHROME` if yours is not at the path
in the scripts.

**The fixture must not change unless a formula deliberately changed.** A diff here is either
a bug you just introduced or a fix you meant to make. If it is a fix, say so in the commit
message and say which numbers moved.

The last verification run covered 2,081 cells across eight season-years (both charts, both
seasons, either side of the spring cutover) with no mismatches.
